# R8 Autopsy Implementation Plan

> **For agentic workers:** use superpowers:executing-plans. Steps use checkbox (`- [x]`) syntax. Built in Kiro (D-R18).

**Goal:** After the remedy, show the necromancer what killed the repo and exactly what was changed to raise it, computed from the real run.

**Architecture:** `buildAutopsy(corpseDir, revivedDir, failure)` diffs the two trees and classifies the changes with a fixed table. `performRitual` emits one `autopsy` ritual event after `remedy` (swallowing any error). It rides the ritual stream, so the recorder and replay carry it. The raise panel renders it as real text with a dot-matrix slab as costume.

**Tech Stack:** TypeScript, Hono, React, Canvas 2D via `useDotCanvas`, Vitest. No new dependencies.

**Spec:** `.kiro/specs/r8-autopsy/{requirements,design,tasks}.md`

## Global Constraints

- Node ≥ 22, ESM, no new deps. `npm run health` green after every task.
- Fresh code only (D-R2). Nothing faked (D-R11): a cause exists only if it is in the real diff.
- `--magic` and `--bone` only; **no `--death` red** (THEME §4). `−`/`+` markers, not colour alone.
- Evidence limits: files ≤ 65536 bytes, 40 lines per cause, 200 chars per line, 12 causes.
- Real text stays real text; every canvas has an `aria-label`; honour `prefers-reduced-motion`.
- Tests beside their code. Old recordings (no `autopsy` event) must still reduce and render.

## Review Focus

- The corpse tree contains a symlink (e.g. `server.js -> /etc/passwd`): its target is never read (Task 3).
- A huge, binary or `node_modules` file is skipped and counted, never loaded into the event (Task 3).
- Remedy changed nothing, or a rejected R9 grave with no rite: empty causes still render and don't throw (Task 3, 4, 6).
- A malformed `package.json` on either side doesn't throw; it falls back to a plain file diff (Task 3).
- An unclassifiable change is still shown as `other`, never dropped (Task 3).
- The autopsy builder throws: the ritual still raises (Task 4).
- Replaying an old recording without the event, or a recorded event with hostile text (`<script>`), renders safely (Task 6, 7).
