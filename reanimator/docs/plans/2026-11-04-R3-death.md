# R3 Death's Attack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** once a ritual has risen, "Summon Death" runs the real Poltergeist engine against the revived app and returns its reproduced findings as wounds.

**Architecture:** the backend spawns the sibling Poltergeist CLI (`summon`) as a subprocess in its own process group (KI-R4). Its spec is the fixture's hand-written chart, copied into the revived repo (KI-R5). Its config and `.poltergeist/` home live in a persistent per-fixture folder, so cached plans survive across rituals. Progress comes from tailing the run's redacted `events.ndjson`. Results come from `haunting-report.json`. Both are streamed to the UI over SSE, with the same resume semantics as the ritual.

**Tech Stack:** TypeScript, Node 22, Hono + SSE, Vitest, React 19; the sibling `../poltergeist` CLI (run through its own `bin/poltergeist.js`, tsx).

**Spec:** `reanimator/docs/PRD.md` § R3, plus the R3 grill decisions Q1–Q12 (recorded as D-R16/D-R17 in Task 9).

## Global Constraints

- Don't re-implement attacks. Call the engine only through its CLI (D-R4, AGENTS rule 3). Never edit `../poltergeist`.
- Death only attacks the local revived app. The config `target` is always the risen ritual's `http://127.0.0.1:<port>` origin (D-R7, Poltergeist D-08).
- Nothing faked (D-R11): a wound is a `haunted` pair from a real report. Flaky and inconclusive pairs are never wounds.
- Argv arrays, never a shell. Every child runs in its own process group (D-R15).
- Child env is an allowlist: `PATH`, `HOME`, `TMPDIR`, `LANG`, `TERM`, `npm_config_*`, plus `PORT`/`HOST` for the app. Only the engine also gets `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `AWS_*` and `NO_COLOR=1`.
- Engine run shape: all six personas (engine default), `reps: 3`, `concurrency: 6`, model default.
- Real text stays real text. `--death` is for Death and wounds only (THEME).
- `npm run health` stays green. Tests never call the network or an LLM.

## Review Focus

1. **The engine exits 2** (no key, bad chart). Expect `failed` with the CLI's `error:` line (without the `error:` prefix), never a hang or a blank. Pinned in Task 5 (`exit 2 → failed`) and Task 8 (the real no-key run).
2. **A new ritual while an attack runs.** Expect the attack to be aborted (its group killed, `failed: stopped`) before the old app is stopped. Pinned in Task 6.
3. **A report with only flaky/clean pairs.** Expect `finished` with zero wounds and the counts shown, not "no report". Pinned in Task 4.
4. **A malformed or missing `haunting-report.json` after exit 0/1.** Expect `failed: the engine wrote no readable report`. Pinned in Task 4/5.
5. **`events.ndjson` lines split across reads.** Expect only whole lines parsed; a partial line is kept until its newline arrives. Pinned in Task 5.

### Task 3: Attack protocol

**Files:** Create `shared/attack.ts`, `shared/attack.test.ts`.

**Interfaces:**
- Produces:
```ts
export interface Wound { criterion: string; text: string; persona: string; reason: string; steps: string[]; expected: string[]; failing: string[]; artifacts: string[] }
export type Counts = Record<'haunted'|'flaky'|'inconclusive'|'clean'|'notApplicable'|'notRun', number>;
export type EngineEvent =
  | { type: 'run.started'; criteria: string[]; personas: string[]; reps: number }
  | { type: 'scout.route'; path: string; status: string }
  | { type: 'plan.compiled'; criterion: string; persona: string; status: string; cached: boolean }
  | { type: 'verdict.criterion'; criterion: string; verdict: string };
export type AttackEvent =
  | { type: 'summoned'; origin: string; only: string[] | null }
  | { type: 'engine'; event: EngineEvent }
  | { type: 'finished'; counts: Counts; wounds: Wound[] }
  | { type: 'failed'; reason: string };
export interface AttackState { status: 'idle'|'attacking'|'finished'|'failed'; origin: string|null; routes: number; plans: number; planned: number; verdicts: Record<string,string>; counts: Counts|null; wounds: Wound[]; failure: string|null }
export const QUIET: AttackState; export function reduceAttack(s: AttackState, e: AttackEvent): AttackState;
export const attackOver: (e: AttackEvent) => boolean; // finished | failed
```
- `planned` = `criteria.length × personas.length` from `run.started`. `plans` counts `plan.compiled`. `routes` counts `scout.route`.
