# R5 Wounds + Heal Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each wound gets a heal brief to hand to Kiro and a **Dare Death again** button. That button re-raises the revived body on real vitals, re-runs the real engine on just that criterion × persona, and closes the wound only on a genuine clean pass.

**Architecture:** The engine's merged `haunting-report.json` (Poltergeist F14) is the ledger. Open wounds are its haunted pairs, carried ones included. A heal run is `summon --only <criterion> --personas <persona>`. A wound is healed when its pair ran in *this* run (no `carriedFrom`) and came back `clean`. Any attack after the first on a ritual stops the app and reruns the four vitals on the same revived dir first, because the app doesn't reload edits. Those vitals stream as `pulse` events in the attack's SSE.

**Tech Stack:** TypeScript, Hono, Vitest, React 19, the existing `runVitals`, `runEngine`, `readWounds` and `useDotCanvas`.

**Spec:** `docs/PRD.md` § R5 · `.kiro/specs/reanimator/requirements.md` Requirement 3 · the grill (recorded as D-R20 in Task 6).

## Global Constraints

- Nothing faked (D-R11): a wound closes only on `verdict === 'clean'` with no `carriedFrom`, in a report whose `runId` is this run's.
- `--death` (red) only for Death and wounds; `--magic` (purple) for healed wounds (the user's necromancy). Never mix.
- Real text stays real text: briefs, wound lines and verdicts are DOM text, not dots.
- `prefers-reduced-motion`: the dissolve is skipped (the healed wound just isn't drawn).
- Don't re-implement Poltergeist: only CLI flags (`--only`, `--personas`) and its report.
- Reanimator never drives Kiro and never writes PRs (D-R10). The brief is copied by the user.
- `npm run health` (from `reanimator/`) stays green after every task.

## Review Focus

1. **Heal for a wound that isn't open** (stale UI, or already healed): the attack ends `failed: that wound is not open`, and the engine never runs.
2. **The heal broke the app** (a vital fails on re-raise): the attack ends `failed: the heal broke the body: <vital>: <first line>`, the app is down, and the next Dare re-raises again instead of 409-ing `notRisen`.
3. **A heal run whose pair comes back carried or missing** (the engine skipped it): `heal.verdict` is `notRun` and the wound stays open.
4. **A new ritual during a re-raise:** the abort reaches `runVitals`, the attack ends `stopped…`, and no app is left running.
5. **A later full attack that re-breaks a healed wound:** it leaves `healed` and is open again.

### Task 3: Re-raising the body and the heal run in `Attacks`

**Files:**
- Modify: `server/ritual.ts`, `server/attack.ts`, `server/app.ts`, `server/main.ts` (only if the constructor changes)
- Test: `server/ritual.test.ts`, `server/attack.test.ts`, `server/app.test.ts`

**Interfaces:**
- Consumes: Task 1's events and Task 2's `readWounds` / `openWounds` / `chartDir` / `runEngine({personas})`.
- Produces:
  - `Rituals.body(id): { revivedDir: string; fixture: Fixture; origin: string | null } | null`. Non-null once the ritual has risen (its log ends `risen`), even after its app was stopped by a failed re-raise.
  - `Rituals.reraise(id, onVital: (r: VitalResult) => void, signal?: AbortSignal): Promise<{ origin: string } | { failed: string }>`:
    - stops the current app;
    - runs `runVitals('revived', revivedDir, fixture, deps, …, signal)`, forwarding each `vital` event's result;
    - on success stores the new app and returns its origin; on failure leaves `app` null and returns `` `${failedVital}: ${firstLine(detail)}` ``.
    - `risen(id)` keeps requiring a live app; `body` doesn't.
  - `Attacks.start(ritualId, o: { only?: string[]; heal?: HealTarget } = {})` (was `start(id, only?)`):
    - `rituals` is typed `Pick<Rituals, 'body' | 'reraise'>`, and `risen` is no longer used here.
    - Unknown or never-risen ritual: `{notRisen:true}`.
    - Run sequence:
      1. `wounds = await openWounds(<chartDir>/haunting-report.json)`, then emit `summoned {origin: body.origin ?? '', only, heal, body: revivedDir, wounds, healed}`.
      2. If `heal` and no wound has its key: `failed: that wound is not open`.
      3. If this isn't the ritual's first attack, or `body.origin` is null: `reraise` (each result → `pulse`). On `{failed}` → `failed: the heal broke the body: <failed>`. Otherwise emit `reraised {origin}`.
      4. `prepareAttack` with the current origin, then `engine` with `only: heal ? [heal.criterion] : only`, `personas: heal ? [heal.persona] : undefined`.
      5. Read with `runId`.
      6. If `heal`: `verdict = pairs[key] && !pairs[key].carried ? pairs[key].verdict : 'notRun'`; if it's `'clean'`, add the healed wound (from the pre-run `wounds`) to the ritual's healed map.
      7. Drop from healed any key that is in the new `wounds`.
      8. Emit `finished {counts, wounds, healed: [...healed.values()], heal: heal ? {...heal, verdict} : null}`.
    - Per-ritual memory: `{ ritual: string; attacks: number; healed: Map<string, Wound> }`, reset when a different ritual id starts.
  - `POST /api/rituals/:id/attack` accepts `{heal:{criterion,persona}}` (both non-empty strings, else 400 `heal must be {criterion, persona}`), passing `{only, heal}`. `AttacksApi`'s `start` signature follows.

**Interfaces:**
- Produces:
  - `healBrief(w: Wound, body: string): string` in `shared/heal.ts`. Plain QA wording, no theme words (like Poltergeist D-09). Its lines, in order:
    - `Fix acceptance criterion <criterion> in the app at <body>: "<text>".`
    - `It fails for the <persona> test persona: <reason>`
    - `Steps:` then `- <step>` for each step
    - `Expected:` then `- <expected>` for each expectation
    - `Failing:` then `- <failing>` for each failing check
    - `The full report is .kiro/specs/chart/haunting-report.md. Do not edit .kiro/specs/chart/requirements.md.`
    - Empty sections are omitted.
  - `requestAttack(fetchFn, ritualId, heal?: HealTarget)` POSTs `JSON.stringify({heal})` with `content-type: application/json` when `heal` is given, and no body otherwise.
  - `useAttack().summon(heal?: HealTarget)`.
  - `AttackPanel`:
    - `attack` gets `Pick<AttackHandle,'state'|'summon'|'error'>` plus an optional `copy?: (text:string)=>Promise<void>`, defaulting to `navigator.clipboard.writeText`.
    - While attacking with `state.heal`: `Death returns for <criterion> · <persona>…`, and each pulse is `<vital> ok|failed` in a list.
    - Wounds show when `state.wounds.length > 0` (during a heal run as well). Each wound has a **Copy for Kiro** button (copies `healBrief(w, state.body)`, then shows `copied`), a **Dare Death again** button (`summon({criterion, persona})`, disabled while attacking), and the text `Open <body> in Kiro` once.
    - After a heal: `healed` → `The wound closed: Death could not break <criterion> again.`; `haunted` → `Death broke it again.`; anything else → `Not proven healed (<verdict>).`
    - `state.healed` is listed as `<li className="healed">… — healed</li>`.
  - `closingPoint(s: AttackState): WoundPoint | null` in `scene.ts`: when `s.status==='finished' && s.healVerdict==='clean' && s.heal`, the point of the healed wound (from `s.healed`, matched by key) placed with the existing `woundSpot` logic, else null.
  - `deathLayer` gets `closing?: { cell: Cell; remain: number }`: it stamps the gash with only the cells whose fixed rank `< remain * 27` (rank = a deterministic permutation of the 27 gash cells, so it dissolves cell by cell).
  - `CLOSE_MS = 1200`; `closingRemain(tMs, startMs, reduce) = reduce ? 0 : 1 - clamp((t-start)/CLOSE_MS,0,1)`.
  - `AttackScene` records `performance.now()` when `closingPoint` first becomes non-null and passes `closing` while `remain > 0`.
  - CSS: `.wounds li.healed { color: var(--magic) }`.
