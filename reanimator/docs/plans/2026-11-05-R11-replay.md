# R11 Hosted Replay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A judge opens a static URL and watches a recorded real run (raise → Death → heal → grimoire) in the real UI, clearly labelled as a replay.

**Architecture:** The backend, when `REANIMATOR_RECORD=<dir>` is set, copies every ritual/attack/spell event it emits (with a timestamp) and every engine frame it streams into a recording bundle. The UI's scene becomes a pure view (`RaiseView`) fed by handles; live mode feeds it the three hooks, replay mode feeds it a player that folds the recorded lines with the **same shared reducers** on a compressed timeline. A `vite build --mode replay` produces a static site; a hand-triggered workflow deploys it to GitHub Pages.

**Tech Stack:** TypeScript, React 19, Vite, Hono, Vitest. No new dependencies.

**Spec:** the R11 grill (decisions Q1–Q13, recorded as D-R22) and `docs/PRD.md` R11.

## Global Constraints

- Nothing faked (D-R11): no synthetic recording is ever published. The test fixture lives under `src/replay/fixtures/` and is never copied into `public/`.
- Label, verbatim: `RECORDED RUN · replay of a real run on <date> · nothing here is live · pauses longer than 2 s are shortened`.
- Bundle format: `recording.json` = `{ format: 'reanimator-recording', version: 1, recordedAt: <ISO> }`; `events.ndjson` lines `{ t: number /* ms since recorder start */, stream: 'ritual' | 'attack' | 'spell', id: string, event }`; frames at `frames/<attackId>/<ghostId>/<seq>.jpg` (seq unpadded).
- Frame byte cap 50 MB (`52_428_800`): past it, frames stop being written (one console warning); lines keep being written.
- Gap cap 2000 ms; speeds 1, 2, 4.
- The home directory is replaced by `~` in every recorded line.
- The recorder refuses (throws) if `<dir>/events.ndjson` already exists. It never deletes.
- Replay is read-only: every button/input in the panel is disabled; no `/api` call is ever made in replay mode.
- `npm run health` green after every task.

## Review Focus

- A recording whose `events.ndjson` has a trailing newline or a blank line → loader skips blank lines (test in Task 4).
- No recording deployed (`recording.json` 404) → page shows "No recording yet" and makes no `/api` calls (test in Task 6).
- Two attacks in one session (first attack, then a heal's re-run) → the replay resets attack state to QUIET on the new id, like `useAttack` (test in Task 4).
- An attack event arriving before its `summoned` frame files exist → recorder must not crash if `attacks.frame` returns null (test in Task 2).
- Page hosted under a sub-path (`/<repo>/`) → art and recording URLs are relative to `import.meta.env.BASE_URL` (test in Task 5).

### Task 2: The recorder (server)

**Files:**
- Create: `server/recorder.ts`, `server/recorder.test.ts`
- Modify: `server/main.ts` (wire when `REANIMATOR_RECORD` is set)

**Interfaces:**
- Consumes: Task 1; `LogSource<E>` from `server/sse.ts`; `RitualsApi`, `AttacksApi`, `GrimoireApi` from `server/app.ts`.
- Produces: `class Recorder { constructor(o: { dir: string; home: string; now?: () => number; capBytes?: number; warn?: (m: string) => void }) ; watch<E>(stream: Stream, id: string, src: LogSource<E>): void; frame(attackId: string, ghostId: string, seq: number, jpeg: Buffer): void }` and `recordApis(apis: { rituals: RitualsApi; attacks: AttacksApi; grimoire: GrimoireApi }, rec: Recorder): same shape`.

Constructor: `mkdirSync(dir, {recursive:true})`; throw `Error('a recording already exists in <dir>; move it away first')` if `events.ndjson` exists; write `recording.json` with `recordedAt = new Date(now()).toISOString()`; `t0 = now()`. `watch` is idempotent per `stream:id`: it replays `src.events(id)` then subscribes, appending each event (`appendFileSync`, `redactHome`) with `t = now() - t0`. `recordApis` wraps each `start` so any returned `id` (including a busy one) is watched; for attacks it also subscribes and, on `{type:'engine', event:{type:'frame'}}`, awaits `attacks.frame(...)` and calls `rec.frame` when non-null. Every other method is passed through. `frame` writes `frames/<attackId>/<ghostId>/<seq>.jpg` unless the cap would be exceeded (then warns once).

- [ ] Tests (tmp dir, fake `LogSource` built on `EventLog`, fake clock): events pushed before and after `watch` both land once, in order, with `t` from the clock; calling `watch` twice records once; home path redacted; second `new Recorder` on same dir throws; frames past `capBytes` are skipped and `warn` called once; `recordApis` with a fake attacks whose `frame` returns `null` doesn't write or throw; `recordApis` writes a frame for an engine frame event.
- [ ] Run `npx vitest run server/recorder.test.ts` → FAIL, implement, → PASS.
- [ ] In `main.ts`: `const dir = process.env.REANIMATOR_RECORD; const apis = dir ? recordApis({rituals, attacks, grimoire}, new Recorder({ dir: resolve(dir), home: homedir() })) : {rituals, attacks, grimoire}`; log `Recording this session to <dir>` when on.
