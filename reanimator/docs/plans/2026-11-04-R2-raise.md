# R2 The Raise Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise a dead repo for real. The backend proves the corpse is dead, applies its remedy and runs the four vitals (install, build, serve, render). The UI shows a spell circle and a heart monitor that go from flatline to pulse exactly as the real vitals pass.

**Architecture:** A repo-agnostic ritual engine in `server/` (fixture loader, command runner, vitals, a one-at-a-time ritual registry) streams `RitualEvent`s over SSE. One pure reducer in `shared/ritual.ts` folds them into `RitualState` on both sides. The raise scene in `src/raise/` draws procedural luminance through the R1 renderer and keeps all real text in a panel. A self-authored "practice corpse" fixture proves it end to end; the real demo repo (KI-R1) drops in later as another fixture folder.

**Tech Stack:** TypeScript, Hono 4 + `hono/streaming` (SSE), Node `child_process`, `playwright-core` 1.64.1 (render vital), React 19, Canvas 2D + `src/render/`, vitest.

**Spec:** `reanimator/docs/PRD.md` § R2, `.kiro/specs/reanimator/requirements.md` Requirement 1, `.kiro/specs/reanimator/design.md` §2, `docs/THEME.md` §4, §5.2, §9, and the R2 grill (recorded as D-R14/D-R15 in Task 7).

## Global Constraints

- Fresh code only (D-R2). Nothing from `../../reanimator` or `../../poltergeist-old`.
- Nothing faked (D-R11): the flatline comes from a real failing vital on the untouched corpse, and a beat comes from a real passing vital. No timers stand in for results.
- `--magic` is only for the user's necromancy (circle, pulse); `--death` is only for the flatline. Never both on one element (THEME §4).
- Real text (vital names, details, the origin) stays as text, never dots (THEME §11).
- `prefers-reduced-motion`: no spin and no scrolling trace; states change instantly (THEME §9). Every canvas gets an `aria-label`.
- The backend binds 127.0.0.1 (D-R12). Every request passes the loopback guard (KI-R12). The revived app listens on 127.0.0.1 only (D-R7).
- No shell strings: commands are argv arrays run with `spawn(argv[0], argv.slice(1), { shell: false })`.
- Pin exact versions (`playwright-core` `1.64.1`, the same as Poltergeist).
- `npm run health` (in `reanimator/`) is green after every task.

## Review Focus

1. **A second "Begin" while a ritual runs**: expect `409`, not a second ritual. A new ritual after the last one finished stops the old revived app first (no orphan process holding a port). The tests are in Task 4.
2. **A command that hangs** (install never returns): it's killed at its timeout, and the vital fails with `timed out after Ns`. The test is in Task 2.
3. **An app that crashes on start**: the serve vital fails as soon as the process exits, with the tail of its output, instead of waiting for the full timeout. The test is in Task 2.
4. **The EventSource reconnects mid-ritual**: with `Last-Event-ID`, the server resends only the missed events, so the folded state never duplicates vitals. The test is in Task 4.
5. **The backend is stopped (Ctrl-C) while an app is revived**: `Rituals.dispose()` stops the child, and `main.ts` calls it on SIGINT/SIGTERM. The test is in Task 4.

// guard.ts — 403 unless Host's hostname is 127.0.0.1 | localhost | [::1] and Origin (if present) is http(s) on one of those
export function loopbackGuard(): MiddlewareHandler;
// ritual.ts
export function performRitual(fixture: Fixture, deps: VitalDeps & { workRoot: string }, emit: (e: RitualEvent) => void): Promise<RunningApp | null>;
export class Rituals {
  constructor(o: { fixture: () => Promise<Fixture>; deps: VitalDeps; workRoot?: string });   // workRoot default os.tmpdir()
  start(): { id: string } | { busy: true };      // stops the previous revived app before starting
  events(id: string, after?: number): { log: RitualEvent[]; done: boolean } | null;   // events with index > after
  subscribe(id: string, fn: (e: RitualEvent, index: number) => void): () => void;
  dispose(): Promise<void>;                      // stops the revived app, removes work dirs
}
// app.ts
export function createApp(o?: { rituals?: Rituals }): Hono;
//   POST /api/rituals → 202 {id} | 409 {error:'a ritual is already running'}
//   GET  /api/rituals/:id/events → SSE; each event `data: <RitualEvent JSON>`, `id: <index>`; honours Last-Event-ID; closes after the terminal event (risen|failed); 404 for an unknown id

- `performRitual` order: emit `started`; mkdtemp `<workRoot>/reanimator-` and copy `corpseDir` → `<tmp>/corpse`, then run vitals `corpse`. **If every corpse vital passes, emit `failed` with reason `not dead: every vital passed before the remedy` and stop that app** (we only raise what is truly dead). Otherwise copy `corpseDir` → `<tmp>/revived`, overlay `remedyDir`, emit `remedy {files}`, and run vitals `revived`. If all pass, emit `risen {origin}` and return the app; if not, emit `failed {phase:'revived', reason:'<vital>: <detail first line>'}`. Any thrown error becomes `failed` with its message.
