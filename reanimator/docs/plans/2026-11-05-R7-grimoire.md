# R7 The Grimoire Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A spellbook panel that drives the real Kiro agent (`kiro-cli`) on the revived body: a spell is a prompt, Kiro's reply is quill writing, its tools are margin notes, its edits are ruled boxes, a finished turn is a wax seal. A spell cast from a wound ends with **Dare Death again** for that wound, so a heal (R5) is driven from the grimoire.

**Architecture:** Each spell is one `kiro-cli chat --no-interactive --output-format stream-json --trust-tools=fs_read,fs_write -- <text>` subprocess in the revived dir (later spells on the same ritual add `--resume`). Its stdout is ACP JSON Lines; a lenient parser (`server/kiro.ts`) turns them into `SpellEvent`s, logged in an `EventLog` and streamed as resumable SSE exactly like the attack. One spell at a time, never while Death attacks (and Death never while a spell is cast). The browser folds the stream with one shared reducer (`shared/grimoire.ts`) and renders DOM text only.

**Tech Stack:** TypeScript, Hono, Vitest, React 19, the existing `runCommand`, `EventLog`, `streamLog`, `childEnv`.

**Spec:** `docs/PRD.md` § R7 · `docs/THEME.md` §8 · the R7 grill (recorded as D-R21 in Task 6).

## Global Constraints

- Nothing faked (D-R11): every line in the grimoire is from Kiro's real stream; the candle burns only from a real `usage_update` (used/size), else it is drawn unlit with "the candle is unlit: Kiro reported no context".
- Kiro's tokens are saved for the demo: no test, script or session step calls the real `kiro-cli`. Tests use `server/fixtures/fake-kiro.mjs` through `REANIMATOR_KIRO`.
- Kiro gets `--trust-tools=fs_read,fs_write` only (no shell), `cwd` = the revived dir, env = `kiroEnv(process.env)` (childEnv + `XDG_*`; never `ANTHROPIC_*`, `AWS_*`, `DOPPLER_*`).
- The spell text is passed after `--` (it may start with `-`). Max 20 000 chars; empty/whitespace → 400.
- Spell timeout 10 min (`SPELL_TIMEOUT_MS = 600_000`); stop/timeout kills the process group (runCommand does).
- Real text stays real text (THEME §8): no canvas in the grimoire. Quill reveals letters client-side; `prefers-reduced-motion` shows all at once.
- Colours: `--magic` for spells and the seal (the necromancer's), `--bone` for quill text, `--dim` for margin notes, `--death` only for failures and the − lines; `--rot` for + lines.
- Reanimator stays the only caller of Death: no Poltergeist `init`/MCP is written into the body (D-R21).
- The heal brief (`shared/heal.ts`) stays plain QA words (no theme words); **Copy for Kiro** stays as the fallback.
- `npm run health` (from `reanimator/`) stays green after every task.

## Review Focus

1. **A stdout chunk that splits a line, or a UTF-8 character, or holds many lines:** each whole line is parsed once, in order (StringDecoder + line buffer). Test in Task 2.
2. **`kiro-cli` missing or not on PATH (ENOENT):** the spell ends `failed: kiro-cli is not installed (or not on PATH)`, nothing hangs. Test in Task 2.
3. **Kiro never exits (a trust prompt in non-interactive mode, a stuck tool):** `POST /api/spells/:id/stop` and a new ritual both end it `failed: stopped…` and kill the child. Test in Task 3 (fake `hang` mode).
4. **A spell starting with `-` or containing quotes/newlines:** reaches Kiro verbatim as one argv entry after `--`. Test in Task 2.
5. **Casting while Death attacks, or summoning Death while casting:** both 409 with a reason, neither process starts. Test in Task 3/4.

  // [cli, 'chat', '--no-interactive', '--output-format', 'stream-json', '--trust-tools=fs_read,fs_write', ...(resume ? ['--resume'] : []), '--', text]

- `toSpellEvents` is lenient about the envelope (the live shape is unverified, KI-R21): the update is `raw.params.update`, else `raw.update`, else `raw` itself if it has `sessionUpdate`. Mapping by `update.sessionUpdate`:
  - `agent_message_chunk` with `content.type === 'text'` → `quill`.
  - `tool_call` / `tool_call_update` → `margin {id: toolCallId, title: title ?? kind ?? 'tool', status: status ?? 'pending'}`, plus one `ruled` per `content[]` item with `type === 'diff'` (`path`, `oldText ?? ''`, `newText`). A `tool_call_update` with no title gives `title: ''` (the reducer keeps the old title when the new one is empty).
  - `usage_update` with numeric `used` and `size` → `candle`.
  - Anything else (thoughts, plans, commands, `user_message_chunk`) → `[]`.
  - A line whose `result.stopReason` (or top-level `stopReason`) is a string → `sealed {stopReason}`; `runKiro` emits only the first seal and never forwards a `sealed` itself — it returns it.
- `runKiro` result: exit 0 → `{ok:true, stopReason: seen ?? 'end_turn'}`; aborted → `{ok:false, error:'stopped'}` (caller words it); timed out → `'Kiro ran past 10 min'`; spawn ENOENT → `'kiro-cli is not installed (or not on PATH)'`; other non-zero → the last non-empty output line.
