# F18 Kiro Power Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Poltergeist as an installable Kiro Power (Agent Plugins format): a committed template in `integrations/kiro/power/`, a `poltergeist power --out <dir>` generator that fills in this checkout's absolute server path, and a `poltergeist-mcp --root-from-spec` mode so one user-level server can serve any project.

**Architecture:** The Power's MCP server is user-level and its cwd is the plugin folder, so it can't have a fixed `--root`. In `--root-from-spec` mode every tool's `specDir` must be an absolute `<project>/.kiro/specs/<name>`, and `<project>` becomes that call's root; the existing `resolveInside`/`findConfig` containment applies unchanged inside it. The generator reads the templates, fills the bin path, validates the bundle against the documented Agent Plugins rules, then writes it into a new or empty folder.

**Tech Stack:** TypeScript (Node ≥ 22, ESM), vitest, `@modelcontextprotocol/sdk` (client in tests), zod 4 (already a dep of mcp; the validator uses plain checks).

**Spec:** `docs/PRD.md` § F18, `.kiro/specs/poltergeist/requirements.md` 10.4, grill decisions D-46 (this plan's Task 5 records them), Power facts in `docs/kiro-notes.md` § Powers (Task 5 rewrites it from the 2026-11-03 research).

## Global Constraints

- Agent Plugins format only: `plugin.json` + `mcp.json` + `skills/poltergeist/SKILL.md`. No `POWER.md`, no hooks in the bundle.
- `plugin.json`: `$schema` = `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`; `name` = `poltergeist` (lowercase, 1–64, `[a-z0-9.-]`, no `--`/`..`, alphanumeric at both ends); `version`, `description`, `author: {name}`, `keywords` all present; `license` = `MIT`.
- Keywords exactly: `poltergeist`, `summon ghosts`, `haunting report`, `rehaunt`, `adversarial acceptance tests`, `haunt spec`. No bare `test`, `api`, `data`.
- `mcp.json`: `$schema` = `https://agent-plugins.org/schemas/1.0.0/mcp.schema.json`; one server `poltergeist`, `type: "stdio"`, `command: "node"` (a single bare token: absolute paths are not allowed for `command`), `args: [<abs bin>, "--root-from-spec"]`, `env: {"ANTHROPIC_API_KEY": "${ANTHROPIC_API_KEY}"}`. No `autoApprove` (not in the plugin schema; Kiro asks before each call). `env` must not contain `PLUGIN_ROOT`/`PLUGIN_DATA`.
- `SKILL.md` frontmatter: `name: poltergeist` (equals its folder), `description` ≤ 1024 chars. Body in plain QA wording (D-09), names all five tools, tells the agent to pass absolute spec paths, never edit `requirements.md`/`design.md`/`tasks.md` (D-14), mentions `poltergeist init` for the hook and per-project steering.
- Kiro namespaces the server as `power-<plugin>-<server>`; `power-poltergeist-poltergeist` + 1 separator + the longest tool name must be ≤ 64.
- Never `npx poltergeist-mcp` (KI-33). Safety rules unchanged (D-05, D-08); `--root-from-spec` never widens a call's root beyond its own project.
- Run `npm run health` after every task; it must exit 0.

## Review Focus

- A relative `specDir` in `--root-from-spec` mode (the agent's habit from the steering file) → `PathError` that says to pass the absolute path, not a silent resolve against the plugin folder.
- `specDir` = `/.kiro/specs/x` or `~/.kiro/specs/x` (project would be `/` or the home dir) → `PathError`; home holds Kiro's user settings, not a project.
- `specDir` with `..` segments or a symlinked `.kiro` pointing outside the project → `PathError` (normalise first, then the existing `resolveInside` realpath check).
- A `configPath` outside the spec's project in `--root-from-spec` mode → `PathError`.
- `--out` that exists and is non-empty, or is a file → `PowerError`, exit 2, nothing written.
