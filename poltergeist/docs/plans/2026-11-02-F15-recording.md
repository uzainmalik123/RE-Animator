# F15 Recording (export, replay, timeline) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A finished run can be exported as a small static recording and replayed over the existing live-feed WebSocket, or scrubbed through a pure timeline. Reanimator (R4 scene, R11 hosted replay) plays it with no target, LLM or browser.

**Architecture:** The event sink also writes `frames.ndjson` (`{ghostId, seq, t}`), so frames can be placed in time. The pure `@poltergeist/core/live` gains `buildTimeline`/`stateAt` (browser-safe). The Node-only `packages/core/src/recording/` gains `loadRecording`/`exportRecording`. The CLI gains `poltergeist export` and `poltergeist replay`, which reuses `startEventServer` with a `recorded` hello.

**Tech Stack:** TypeScript (Node ≥ 22, ESM), vitest, ws 8.22.0, zod 4. No new dependencies.

**Spec:** `.kiro/specs/poltergeist/requirements.md` Req 11.4. `docs/PRD.md` F15, re-scoped by the 2026-11-02 grill (recorded as D-43 in Task 6). `design.md` §8–9.

## Global Constraints

- Replay touches no target, LLM or browser (Req 11.4). It reads only the recording folder.
- The recording is labelled recorded: the manifest has `recorded: true`, and `live.hello` carries `recorded: true` (Req 11.4).
- Bundle cap: 50 MB by default (`--max-mb`, an integer from 1 to 1000).
- `LIVE_PROTOCOL` stays `1`. New fields are optional and additive.
- `packages/core/src/live/` imports nothing from Node or Playwright (D-40).
- The bundle never contains `run.json`, `plans/`, `scout/` or `artifacts/`.
- `export` never deletes anything. `--out` must not exist or must be an empty directory, and must not be inside the run folder.
- Replay `--speed`: a number from 1 to 16, default 1. The WS is on `127.0.0.1:6660/runs/<runId>`, the same server as `--seance`.
- Commit messages: `F15: <what>`.

## Review Focus

- A run folder from before this change (no `frames.ndjson`): it must still load. Frame times are estimated between the ghost's `ghost.spawned` and its rep's `rep.finished` (Task 2 test).
- A truncated or corrupt last line in `events.ndjson` (the process was killed mid-write): skip it with a warning, don't throw (Task 2 test).
- An `--out` inside the run folder, or one that's non-empty: refuse with `RecordingError`, write nothing (Task 3 test).
- An aborted run (no `run.finished`): replay still plays to the last event and exits 0 (Task 5 test).
- A replay client that never connects: Ctrl-C (abort) exits 130 and closes the server (Task 5 test).

### Task 2: Pure timeline and `loadRecording`

**Files:**
- Create: `packages/core/src/live/timeline.ts` (pure), and export it from `live/index.ts`
- Create: `packages/core/src/recording/load.ts`, `packages/core/src/recording/index.ts`, and export it from `src/index.ts` (not from `/live`)
- Test: `packages/core/test/live/timeline.test.ts`, `packages/core/test/recording/load.test.ts`

**Interfaces:**
- Produces (live, pure):
  - `type FrameMark = { ghostId: string; seq: number; t: number }`
  - `type TimelineEntry = { at: number; event: SummonEvent } | { at: number; frame: FrameMark }`, where `at` is ms since the first event's `t` (clamped ≥ 0)
  - `buildTimeline(events: readonly SummonEvent[], frames: readonly FrameMark[]): TimelineEntry[]`: stable sort by `at`. An event sorts before a frame with the same `at`. A frame whose ghost has no `ghost.spawned` is dropped.
  - `estimateFrameTimes(events, frames: readonly {ghostId; seq}[]): FrameMark[]`: a ghost's frames are spread evenly over (spawned.t, end), where end is the `rep.finished` t for its rep, or else the last event's t.
  - `timelineDuration(tl): number` (the last `at`, or 0)
  - `stateAt(tl, ms: number, frameData?: (f: FrameMark) => string | undefined): LiveState`: folds entries with `at <= ms`. A frame becomes a `ghost.frame` message only when `frameData` returns base64.
- Produces (Node):
  - `type Recording = { dir: string; runId: string; events: SummonEvent[]; frames: FrameMark[]; estimatedFrames: boolean; timeline: TimelineEntry[]; readFrame(f: FrameMark): Promise<Buffer> }`
  - `loadRecording(dir: string, opts?: { onWarning?(m: string): void }): Promise<Recording>`. It reads `events.ndjson` (required) and `frames.ndjson` (or lists `frames/<ghostId>/*.jpg` and estimates times). `runId` comes from `run.started`.
  - `class RecordingError extends Error`, for a missing `events.ndjson` or no `run.started`.
  - Frame marks whose jpg is missing are dropped. `readFrame` reads `framePath(ghostId, seq)` under `dir`.

- [ ] Step 1: Timeline tests: ordering with ties, the dropped orphan frame, `stateAt(tl, 0)` (phase `scouting`), `stateAt(tl, timelineDuration(tl))` deep-equals `foldLive(events)` when there is no `frameData`, and `stateAt` with `frameData` sets the ghost's `frame.seq`. An estimate test: ghost spawned at t=100, its rep finished at t=400, 2 frames → t 200 and 300.
- [ ] Step 2: Load tests (temp dir): a written run with `frames.ndjson` loads with `estimatedFrames:false`; delete `frames.ndjson` → `estimatedFrames:true`, with the same frame count; a corrupt last ndjson line → it loads, and `onWarning` is called once; no `events.ndjson` → `RecordingError`.
- [ ] Step 3: Run both files. Expected: FAIL.
- [ ] Step 4: Implement.
- [ ] Step 5: Rerun. Expected: PASS. Commit `F15: timeline and loadRecording`.

### Task 3: `exportRecording`

**Files:**
- Create: `packages/core/src/recording/export.ts`, and export it from `recording/index.ts`
- Test: `packages/core/test/recording/export.test.ts`

**Interfaces:**
- Consumes: `loadRecording`, `FrameMark`.
- Produces:
  - `type RecordingManifest = { format: 'poltergeist-recording'; version: 1; recorded: true; runId: string; target: string; criteria: string[]; personas: string[]; reps: number; counts?: Record<PairVerdict, number>; haunted: string[]; durationMs: number; frames: number; droppedFrames: number; exportedAt: string }` (`durationMs` = `timelineDuration`)
  - `exportRecording(opts: { runDir: string; outDir: string; maxBytes?: number /* default 50*1024*1024 */; now?: () => Date; onWarning? }): Promise<{ outDir: string; bytes: number; manifest: RecordingManifest }>`
  - The bundle holds `recording.json`, `events.ndjson` (rewritten from the loaded events), `frames.ndjson` (the kept marks, with real or estimated `t`), `frames/<ghostId>/<seq>.jpg` (the kept ones, original names), and `verdicts.json` when present.
- **Thinning** (decided here): the protected frames are each ghost's last frame, plus every frame of a ghost that failed an assertion (`assert.result` ok:false for its criterion+persona+rep). While the total size exceeds `maxBytes`, drop every other unprotected frame of each ghost (keeping the even-indexed ones). Stop when nothing more can drop, then throw `RecordingError` (`recording is N MB, over the M MB cap even after thinning`) before writing anything. Sizes come from `stat`.
- **Out-dir safety:** resolve both paths. `outDir` inside `runDir`, or equal to it, → `RecordingError`; an `outDir` that exists and is non-empty → `RecordingError`. Both are checked before any write.

- [ ] Step 1: Tests on a synthetic run dir (events with a failed assert for ghost A, 6 frames each for A and B of a known size):
  - a full export copies all 12 and `manifest.droppedFrames === 0`;
  - a `maxBytes` that forces thinning keeps all 6 of A and B's last frame, with `bytes <= maxBytes`;
  - a `maxBytes` too small → throws, and `outDir` doesn't exist;
  - a non-empty out → throws; out = `join(runDir,'x')` → throws;
  - the bundle has no `run.json`, `plans` or `artifacts` even when the run dir has them;
  - `loadRecording(outDir)` round-trips the events and kept frames.
- [ ] Step 2: Run. Expected: FAIL.
- [ ] Step 3: Implement.
- [ ] Step 4: Rerun. Expected: PASS. Commit `F15: exportRecording with thinning`.
