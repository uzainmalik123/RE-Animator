# F21 Headless Sandbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `poltergeist sandbox`: a locked, public-safe HTTP + WebSocket server around `summon` that lets anyone start a real haunting of one fixed project from cached plans only, one run at a time, rate-limited, and watch it on the live feed.

**Architecture:** Re-scoped under D-39 (grilled 2026-11-03, D-49). The engine ships the server; the container, Candy Swap inside it, and the public deploy are Reanimator R11's and tracked as KI-70. The sandbox never builds an LLM client (`cacheOnlyLlm()` turns a cache miss into an `uncompilable` pair). The backlog/broadcast logic of `seance-server.ts` is extracted into `live-broadcast.ts` so the sandbox and `--seance` share it. A `SandboxRuns` manager owns single-flight, timeout and retention; `startSandbox()` is the `node:http` + `ws` (`noServer`) front.

**Tech Stack:** TypeScript (Node ≥ 22, ESM), `node:http`, `ws`, vitest, the claims fixture.

**Spec:** PRD F21 (`docs/PRD.md`) as re-scoped by the grill → D-49; `.kiro/specs/poltergeist/requirements.md` Requirement 11 (new 11.5).

## Global Constraints

- Targets stay loopback-only via the config allowlist (D-05); the sandbox adds no way to change config, target, reps or concurrency from a request.
- No LLM call ever (cache-only); no `recompile`.
- Default bind `127.0.0.1:6662`; `--host` other than loopback prints `warning: sandbox listening on <host>: anyone who can reach it can start runs`.
- Defaults: `--per-client-hour 6` (0 = unlimited), `--run-timeout 300` s (10–3600), `--keep 5` (1–50), request body ≤ 4096 bytes.
- `LIVE_PROTOCOL` stays 1; the hello is unchanged.
- No local paths leave the server: `run.started` is sent as `{...e, runDir: '.', specDir: basename(e.specDir)}` (same rewrite as D-43 export).
- Prune only run folders this server created (paths from its own runs' `run.started`), never anything else.
- `npm run health` green after every task. Commit messages `F21: <what>`.

## Review Focus

- A POST while a run is going → 409 and it does not count against the client's rate limit (Task 5 test `busy does not count`).
- A summon that throws (UsageError: unknown criterion id) → 400 with that message, run not kept; any other error → run `failed` with `error: 'run failed'`, server stays up (Task 4/5 tests).
- Malformed body (not JSON, array, `only` not a string array, > 4096 bytes) → 400/413, no run starts (Task 5 test).
- A late WS client on a finished, still-kept run gets hello + backlog and folds the same board (Task 5 test `late joiner on finished run`); an evicted run's WS/GET → 404.
- Run timeout aborts the summon via the signal and marks it `aborted`; the next POST works (Task 4 test).

### Task 4: `SandboxRuns` manager

**Files:**
- Create: `packages/cli/src/sandbox/runs.ts`
- Test: `packages/cli/test/sandbox/runs.test.ts` (fake `SummonFn` that emits events through `opts.onEvent` and resolves/rejects/hangs-until-abort)

**Interfaces:**
- Consumes: `createLiveBroadcast` (Task 2), `cacheOnlyLlm`, `publicEvent`, `newRunId`, `UsageError` (Task 1 / core).
- Produces:
  ```ts
  export type SandboxStatus = 'running' | 'finished' | 'failed' | 'aborted';
  export type SandboxSummary = { runId: string; status: SandboxStatus; startedAt: number; finishedAt?: number;
    criteria?: { id: string; verdict: string }[]; haunted?: string[]; counts?: Record<string, number>;
    changes?: { id: string; from: string; to: string }[]; cacheMisses?: number; durationMs?: number; error?: string };
  export type SandboxRunsOptions = { specDir: string; configPath?: string; cwd: string; env: NodeJS.ProcessEnv; reps?: number;
    runTimeoutMs: number; keep: number; summon?: SummonFn; summonOverrides?: Pick<SummonOptions,'launch'|'runOptions'>; log?: (m: string) => void };
  export class SandboxBusyError extends Error { constructor(readonly activeRunId: string) }
  export class SandboxRuns {
    start(req: { only?: string[]; personas?: string[] }): Promise<string>; // resolves with runId once run.started is seen; rejects UsageError / SandboxBusyError
    get(runId: string): { summary: SandboxSummary; broadcast: LiveBroadcast } | undefined;
    list(): SandboxSummary[]; // newest first
    activeId(): string | undefined;
    close(): Promise<void>; // aborts the active run, awaits it, closes all broadcasts
  }
  ```
- Behaviour: `start` passes `llm: cacheOnlyLlm()`, `recompile: false`, its own `runId`, and an AbortSignal that fires after `runTimeoutMs`. Every event goes through `publicEvent` into the run's broadcast; the real `runDir` is remembered from the raw `run.started`. If summon rejects **before** `run.started` → `start` rejects with that error (UsageError passes through; others become `new Error('run failed')`), nothing is kept. After `run.started`: resolve → `finished` with `criteria = result.merged`, `haunted`, `counts = result.verdicts.counts`, `changes`, `cacheMisses` = pairs `uncompilable` whose reason contains `CACHE_ONLY_MESSAGE` (log `warning: <n> cache misses; warm the cache with poltergeist summon`), `durationMs`; reject with the signal aborted → `aborted`; any other rejection → `failed`, `error: 'run failed'` (real message only to `log`). On settle the broadcast stays open so late joiners still get the backlog; `closeAll(1001, 'evicted')` only on eviction or `close()`. Before each `start`, evict the oldest settled runs so at most `keep − 1` remain, `rm -rf` their remembered `runDir`.

- [ ] **Step 1:** Tests: (a) start → summary `running` → after resolve `finished` with criteria/haunted/cacheMisses 1 (fake result has one cache-miss pair); (b) second `start` while running rejects `SandboxBusyError` with the active id; (c) UsageError before `run.started` rejects with it and `list()` is empty; (d) a summon that waits for its signal, with `runTimeoutMs: 50` → `aborted`, and a following `start` works; (e) generic error after `run.started` → `failed`, `error: 'run failed'`; (f) `keep: 2`, three runs with real temp `runDir`s → first is gone from `list()`/`get()` and its folder is deleted, the others exist; (g) summon receives `llm` whose `complete` rejects with `CACHE_ONLY_MESSAGE` and `recompile: false`; (h) a broadcast-attached fake ws sees `run.started` with `runDir: '.'`.

### Task 5: HTTP + WebSocket front `startSandbox()`

**Files:**
- Create: `packages/cli/src/sandbox/server.ts`, `packages/cli/src/sandbox/index.ts`
- Test: `packages/cli/test/sandbox/server.test.ts` (fake summon, `port: 0`, real `fetch` and `ws`)

**Interfaces:**
- Consumes: `SandboxRuns` (Task 4), `createRateLimiter`, `clientKey` (Task 3).
- Produces: `startSandbox(opts: SandboxRunsOptions & { host?: string; port?: number; perClientHour: number; trustProxy: boolean; now?: () => number }): Promise<{ url: string; close(): Promise<void> }>`; `SANDBOX_PORT = 6662`.
- Routes (every response JSON with `access-control-allow-origin: *`, `cache-control: no-store`; `OPTIONS *` → 204 with `access-control-allow-methods: GET, POST, OPTIONS` and `access-control-allow-headers: content-type`):
  - `GET /health` → 200 `{ok: true, busy: boolean, activeRunId: string|null, runs: number}`
  - `POST /runs` → body optional (empty = `{}`), must be a JSON object with only `only`/`personas`, each an array of ≤ 64 non-empty strings ≤ 32 chars → else 400 `{error}`; > 4096 bytes → 413. Order: validate body → busy? 409 `{error:'busy', runId}` → rate limit? 429 `{error:'rate limited', retryAfterSec}` + `retry-after` header → `runs.start` → 202 `{runId, status: '/runs/<id>', live: '/runs/<id>/live'}` and `limiter.record(key)`; UsageError → 400 `{error: message}`; other → 500 `{error:'run failed'}`.
  - `GET /runs` → 200 `{runs: SandboxSummary[]}`; `GET /runs/<id>` → 200 summary or 404.
  - WS upgrade on `/runs/<id>/live` for a kept run → `broadcast.attach(ws)`, any origin, `maxPayload: 1024`; else `socket.destroy()` after writing `HTTP/1.1 404 Not Found`.
  - Anything else → 404 `{error:'not found'}`; wrong method on a known path → 405.
- `close()` closes the http server, terminates WS clients and calls `runs.close()`.
